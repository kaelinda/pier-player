# Pier Player 产品优化设计

## 目标

提升当前 macOS 原型的安全性、信息透明度和后续 UI 可维护性，同时保持现有 SMB、FFmpeg、诊断和 CloudKit 架构不变。

## 改动范围

### 来源管理

- 删除来源先进入 `confirmationDialog`，显示来源名称并说明只删除本机连接配置，不删除 NAS 文件。
- 确认后复用现有 `AppModel.removeSource(id:)`，不改变存储协议。

### 媒体库扫描反馈

- 将默认扫描深度和视频数量上限集中为可展示的文案来源。
- 当扫描达到视频数量上限时，在媒体库状态区域显示提示，并保留浏览来源入口。
- 不改变当前扫描上限和扫描算法，避免本轮引入增量索引范围扩大。

### UI 维护性和可访问性

- 将媒体库中重复的卡片/Artwork 相关实现拆为独立 SwiftUI 类型，保持现有布局与交互。
- 移除重要信息上的 `caption2` 使用，改用至少 `caption`。
- 保留 Reduce Motion、focus、hover 和现有 accessibility label 行为。
- 用共享设计常量收敛本轮新增或调整的尺寸、圆角和色彩值。

### 播放时间格式

- 保留现有 `0:00`、`1:05`、`1:01:01` 的显示契约。
- 将基于 `String(format:)` 的 UI 时间字符串改为 Swift 原生字符串拼接/格式化实现，避免 C 格式化与本地化边界。

### 文档同步

- 更新 README 的当前能力、已知限制和跨平台状态。
- 删除已被实现淘汰的“尚不支持 FFmpeg、字幕、轨道选择”等描述。
- 明确仍未完成的 HDR/Dolby Vision、位图字幕、元数据刮削、iOS/tvOS 和大规模增量索引能力。

## 验证

- `swift build` 必须通过。
- 运行与媒体库状态、来源管理、播放时间相关的现有测试。
- 检查工作区 diff，确认没有修改 `app/Vendor`、凭据或本地数据。

## 非目标

- 不新增元数据服务或网络协议。
- 不重写 FFmpeg 播放内核。
- 不实现 iOS、iPadOS 或 tvOS UI。
- 不改变扫描上限、来源存储 schema 或诊断包格式。
